## 3. スキル①：顧客データベース管理

### 何ができるか
- 顧客ごとの **YAML frontmatter付きMarkdownファイル** で全情報を一元管理
- 構造化データなので機械可読・人間にも読みやすい
- Git で版管理 → 変更履歴・rollback可能

### ファイル
- `customers/<id>.md` — 顧客本体（8ファイル）
- `templates/new-customer.md` — 新規顧客追加用ひな型

### Frontmatter共通フィールド
```yaml
id: 顧客ID（ファイル名と一致）
display_name: 表示名（〇〇さん形式）
real_name: 本名（あれば）
nickname: あだ名・別名
status: 現在のステータス（PLAYBOOK.mdの定義に従う）
priority: P0 / P2 / P3
plan: プラン名
plan_price: 価格（数値・¥なし）
contact_method: LINE / Discord / メール
daw: DAW名
dtm_years: DTM歴
genre: 主ジャンル
references: [参考アーティスト or 楽曲]
acquisition_channel: 流入経路（公式LINE等）
proposal_target_plan: 提案候補プラン
next_action: 次にやること
next_action_due: 期限
last_updated: 更新日
```

### 使い方
- 顧客とやり取りしたら **必ず `last_updated` と `next_action` を更新**
- 重要な技術FBは「これまでのFB記録」セクションに1〜2行追記
- 履歴は時系列で「対応履歴」セクションに残す
- ステータス変更時は `status` だけでなく該当する行動履歴も書く

## 5. スキル③：オンボーディング

### 何ができるか
- 新規LINE登録 → テンプレ返信受信時の標準対応フロー
- 完全初心者から中級者まで、レベルに合わせた初回返信が組める

### 確認済みパターン（やすさん・雄太さんで実証）
1. **歓迎・称賛**：DTM挑戦している姿勢を肯定
2. **構成要素＋展開のフレーム**：
   - キック&ベース／ドラム／メロディ／FX／アンビエンス
   - イントロ→ビルドアップ→ドロップ→ブレイク→フック→ビルドアップ→ドロップ2→アウトロ
3. **「真似することから始める」**：完コピ → 後でアレンジ
4. **参考曲を引き出す問いかけ**で締める
5. **ロードマップ案内は絶対に入れない**（信頼関係なし段階）

### LINEオンボーディングのフルシーケンス
1. 登録時：豪華特典4個＋プラグイン徹底解説ガイド配布
2. 「相談」コマンド → 特典②（ベースラインMIDI 10選＋Serumプリセット）配布
3. テンプレ返信4項目を求める：

4. テンプレ返信受領 → CRM登録 → 24時間以内に第1回返信

→ この4項目がそのまま `customers/<id>.md` の frontmatter に直接マッピング可能

## 6. スキル④：楽曲フィードバック作成

### 何ができるか
- 顧客から音源（or 質問）を受領 → トリケラテクノ流の構造化されたFBを返す
- 段階的なFB（①→②→③）で背中を押し続ける

### 確認済みパターン

#### A. 楽曲FBの基本フロー（5部構成）
1. 共感（その悩みは独学のほぼ100%が通る）
2. 良い点を**具体的に**2〜3個（一般論NG）
3. 改善は**1点だけ**に絞る（最大インパクト）
4. 次にやってほしいこと1つ（小さく今週中）
5. 問いかけで締める

#### B. ジャンル別FB特化パターン
| ジャンル | 確認済み定番アプローチ |
|---|---|
| **PsyTrance（hirokazoo）** | 60〜200Hzのボディ／OTT 15%／キック→サチュ→ダッキングの段階的FB |
| **Techno/Tech House（DAIKI）** | キック強化① サンプル変更 → ② サチュレーション10% → ③ ダッキング |
| **歌モノ（TatsuyaN）** | ボーカル前出し／ベースタイミングをキック後にずらす（同タイミングNG）／リバーブ過多対策 |
| **Frenchcore/Speedcore（なつき）** | ドロップ以外を痩せさせる引き算設計／800Hz中域飽和対策 |
| **ジブリ×ダンス（Minoru）** | Sub Bass確保／Low Mid詰まり／High Mid抜け感／Clap/Snapパン振り |
| **Progressive House（ATSUKI）** | 中高域不足（OTT 20%＋サチュ Drive +3dB）／ボーカル×シンセ帯域被り（ダイナミックEQ）／ボーカル前出しは倍音で／第2のメロディをBreakに足す（pluck系アルペジオ） |
| **EDM（雄太）** | キック&ベース→ドラム→メロディ→FX→アンビエンスの構成要素・展開を学ぶ |

## 8. スキル⑥：緊急対応

### 何ができるか
- 想定外事態が発生した時、慌てず・取り違えず・後悔しない判断を支援

### カバーしている8パターン
1. **返金申請** — 48時間以内かチェック→処理→記録
2. **クレーム・苦情** — 言い訳しない・論破しない・まず謝る・24時間以内一次回答
3. **期限の約束を守れない** — 1分でも過ぎる前に連絡＋新期日提示
4. **離脱・休止** — 追わない・関係維持の窓は閉じない
5. **Stripe決済トラブル** — 二重決済は即返金・カード情報を直接聞かない
6. **データ・ファイル紛失** — 隠さない・即報告・再発防止策提示
7. **名前混同事故** — 言い訳NG・誤送信は即訂正＋謝罪
8. **SNS公開トラブル** — 公開で論争しない・DMに移す

### ファイル
- `crm/PLAYBOOK_EMERGENCY.md`

### 困った時の判断フロー
```
事態発生
  ↓
PLAYBOOK_EMERGENCY.md を開く
  ↓
該当パターンあるか？
  ├ YES → 該当節の手順
  └ NO → 以下を自問
        1. 顧客の信頼が一番回復する選択は？
        2. 自分の感情と切り離して判断できるか？
        3. 24時間後の自分が後悔しない選択か？
  ↓
即時対応 → log/ に記録 → PLAYBOOK更新
```

## 11. スキル⑨：確認済み教え方ナレッジ

### 共通の指導哲学（確認済み）
- **「真似することが上達の近道」**（独学派が抵抗を感じる部分を肯定する）
- **「最初から1曲全部作ろうとすると止まる」**（小さなセクションから）
- **「ドロップだけ作る」「4〜8小節だけ作る」**（具体的な小課題）
- **「1記事=1タスク」**（情報量を区切る）
- **「自分で考えるより、まず分解して理解」**

### 確認済み技術ナレッジ

#### ミックス全般
- **中高域不足対策**：OTT Mix 20%前後 + サチュレーター Drive +3dB前後 + マスターで2k〜8kHz +3dB
- **ボーカル×シンセ帯域被り対策**：①2〜4kHzカット ②ダイナミックEQ（ボーカル鳴ってる時だけシンセ中域下げ） ③サイドチェイン -3dB ダッキング
- **リバーブ過多対策**：①Mix量を下げる ②センド分離＋ダッキング
- **ボーカルを前に出す**：音量NG。**倍音を足す**（OTT/サチュレーター）
- **「お風呂で歌っている感覚」** = 共感ポイントとして使える表現

#### キック強化（PsyTrance/Techno）
- ① サンプル変更（60〜200Hzのボディ重視・キックニンジャ）
- ② サチュレーション10%（音量上げずに存在感を出す）
- ③ ダッキング（ボーカル・メロディに-3dB）

#### ベースとキックの関係
- **キックとベースを同タイミングで打つと低域でぶつかる**
- 解決：**ベースをキックの "後" にずらす**（位置の問題・音色は問題ない）

#### マスタリング/LUFS
- **LUFS -7〜-8 はOK**（業界標準・特にメロディックテクノ）
- 問題はLUFS値ではなく **どれだけ圧縮しているか**
- リミッター GR：**最大 -5dB / 平均 -3dB が圧縮下限**
- 超えると：ダイナミクスがつぶれる／平坦になる／ドロップの抜けが消える

#### Break構成の個性化（Progressive House）
- **「2つ目のメロディを足す」** — pluck系アルペジオで第2メロディ
- 1stドロップ終わり〜2ndビルドアップにかけて配置
- 既存ピアノ・コードを段階的に自分のメロディに置き換える

#### MIDI変換
- **ドラムロールをMIDI変換すると失敗しやすい**（ピッチ多くて変換器が混乱）
- 解決：①サンプルそのまま使う ②Drum Rackで耳コピ再現
- ピアノ等のMIDI変換は「ざっくり型を出して→自分で修正」が有効

#### 楽曲構造（ダンスミュージック）
- **要素**：キック&ベース／ドラムス／メロディ／FX／アンビエンス
- **展開**：イントロ→ビルドアップ→ドロップ→ブレイク→フック→ビルドアップ→ドロップ2→アウトロ
- **「盛り上げる・期待感を出す」=楽器選びより配置の問題**

### ⚠️ Claude が一般知識で書いた可能性のある領域（要確認）
- Studio One特有のプラグイン名（Mai Tai / Mojito / Impact XT）
- Youlean Loudness Meter 推奨
- Break個性化テクニック A〜E（音色差し替え・リズム停止→再起動・ボーカルチョップ・転調・環境音レイヤー）— トリケラテクノさんは「2つ目のメロディ」を推す

## 19. このCRMで「絶対にやらないこと」

- ❌ 名前を取り違えて返信を送る（致命的事故）
- ❌ 約束した期日を黙って過ぎる
- ❌ 押し売りトーンでアップセル提案
- ❌ 投げ銭・サポート歴を「だから払って」風に利用
- ❌ 一般論で「先生の見解」のように書く（Claudeが勝手に作らない）
- ❌ 既存顧客（旧プラン）と新規顧客（新プラン）を混同
- ❌ 個人情報（実名・メール・SoundCloud等）をリポジトリ外に持ち出す
- ❌ 24時間以上 P0 顧客への返信を止める
- ❌ 楽曲FBで「すごい」「いいですね」だけの抽象論で終わる
- ❌ 段階的FBの順序を破る（①なしで②に行く等）
